# Confidential Document Q&A Workbench

A multi-agent AI workbench for confidential organizational documents. Upload
PDF/DOCX files and interact with them through three specialist agents —
**Summarizer**, **Q&A (RAG)**, and **Comparator** — automatically routed by a
**LangGraph orchestrator**.

Document storage, chunking, embeddings, and vector search (ChromaDB) all run
**locally**. LLM inference (routing, summarization, Q&A generation, and
comparison) is provided by the **Google Gemini API**.

> ⚠️ **This application is not fully offline.** Document content that is sent
> to an agent (chunks used for summarization, retrieved context for Q&A, and
> document text for comparison) is transmitted to Google's Gemini API over
> the network. Only document storage, chunking, and embeddings stay local.
> Review Google's API terms and your organization's data-handling policies
> before using this with real confidential documents.

---

## 1. Overview

| Capability | How it works |
|---|---|
| Document ingestion | PDF/DOCX → text extraction → chunking → **local** embeddings → **local** ChromaDB |
| Summarization | Chunk-level ("map") summaries combined into a final ("reduce") summary with key points, findings, conclusion — generated by **Gemini** |
| Q&A | Retrieval-augmented generation: local ChromaDB retrieval + **Gemini**-generated grounded answer, with filename + page citations |
| Comparison | Line-level diff hints (local `difflib`) + **Gemini** semantic analysis → structured added/removed/modified/unchanged/important-changes table |
| Routing | **Gemini** classifies each request into `summarizer`, `qa`, `comparator`, `multi_agent`, or `unsupported` — not a keyword if/else chain |

## 2. Architecture

```
                     ┌────────────────────┐
   User query   ───► │   LangGraph         │
                     │   Orchestrator       │  (Gemini-based intent classification)
                     └─────────┬───────────┘
                               │
            ┌──────────────┬──┴───────────┬───────────────┐
            ▼              ▼              ▼               ▼
     ┌─────────────┐ ┌───────────┐ ┌──────────────┐ ┌─────────────┐
     │ Summarizer   │ │  Q&A/RAG  │ │  Comparator   │ │ multi_agent │
     │ Agent        │ │  Agent    │ │  Agent        │ │ (compose)   │
     └──────┬───────┘ └─────┬─────┘ └──────┬───────┘ └──────┬──────┘
            │               │              │                │
            └───────────────┴──────┬───────┴────────────────┘
                                    ▼
                    ┌────────────────────────────────┐
                    │  ChromaDB (local)               │◄── local HF embeddings
                    │  Google Gemini API (cloud LLM)   │◄── requires GEMINI_API_KEY
                    └────────────────────────────────┘
                                    │
                                    ▼
                            Final Response
                        (with sources + explainability)
```

All agents share a single typed LangGraph state object (`graph/state.py`)
containing the user query, routing decision, retrieved context, intermediate
results, final response, sources, and errors — this is how agents
"communicate" through the workflow.

## 3. Features

- **Persistent local knowledge base** — ChromaDB stored on disk under `data/chroma/`.
- **Local embeddings** — HuggingFace `sentence-transformers/all-MiniLM-L6-v2` runs on-device; document text is never sent anywhere just to be embedded.
- **SHA-256 duplicate detection** — identical files are never re-embedded.
- **Delete / re-index / view indexed documents**, with chunk + document counts.
- **Page-aware citations** for PDFs; DOCX citations reference the document as a whole (DOCX has no native page concept).
- **Grounded answers only** — the Q&A agent is instructed never to invent information, and explicitly says *"The answer was not found in the indexed documents."* when retrieval comes up empty.
- **Explainability panel** — selected agent, routing reason, documents used, retrieved chunks, LLM model, processing time, and sources are all shown (no hidden chain-of-thought).
- **System health checks** on the Dashboard: Gemini API key configuration status (with an on-demand "Test Gemini connection" check), local embedding model availability, ChromaDB availability.
- **Graceful error handling** everywhere — corrupted files, empty documents, duplicate uploads, a missing/invalid Gemini API key, a temporary Gemini API outage, missing comparison documents, and empty questions are all handled without crashing the app.
- **Configurable settings** — Gemini model name, temperature, chunk size/overlap, top-K retrieval.
- **The Gemini API key is never logged, hardcoded, or displayed** — the UI only ever shows "Configured" / "Missing".

## 4. Installation

### 4.1 Prerequisites

- Python 3.10+
- A Google Gemini API key — get one at [Google AI Studio](https://aistudio.google.com/apikey)
- Outbound internet access to Google's Generative Language API
- ~2 GB free disk space (local embedding model only; no local LLM weights are needed anymore)

### 4.2 Clone / copy the project and install dependencies

```bash
cd confidential-document-workbench
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 4.3 Configure your Gemini API key

Copy the example environment file and fill in your real key:

```bash
cp .env.example .env
```

Edit `.env`:

```
GEMINI_API_KEY=your_actual_key_here
```

`.env` is already listed in `.gitignore` and is loaded automatically via
`python-dotenv` on startup — **never commit this file or hardcode the key in
source**. You can alternatively export the variable directly in your shell
instead of using a `.env` file:

```bash
export GEMINI_API_KEY=your_actual_key_here   # Windows: set GEMINI_API_KEY=your_actual_key_here
```

If the key is missing, the app will start normally, but the Dashboard and
Settings pages will clearly flag "GEMINI_API_KEY is not configured", and any
attempt to use an agent will show a helpful, non-crashing error message
instead of silently failing.

## 5. Running the app

```bash
streamlit run app.py
```

Then open the URL Streamlit prints (typically `http://localhost:8501`).

On first run:
1. Go to **Dashboard** to confirm the Gemini API key is configured and (optionally) click **Test Gemini connection**.
2. Go to **Documents** and upload one or more PDF/DOCX files.
3. Go to **Ask Documents** to chat — the orchestrator will route your request automatically.
4. Or use **Summarize** / **Compare** directly for an explicit agent.

The first time the embedding model is used, `sentence-transformers` will
download `all-MiniLM-L6-v2` from HuggingFace and cache it locally
(`~/.cache/huggingface`). After that first download, embeddings and retrieval
run without any network access — but LLM calls (routing, summarization, Q&A
answers, comparisons) always require network access to the Gemini API.

## 7. Multi-agent workflow (routing)

The orchestrator prompts Gemini to return **strict JSON**:

```json
{"route": "qa", "reason": "The user asked a specific factual question."}
```

Valid routes: `summarizer`, `qa`, `comparator`, `multi_agent`, `unsupported`.

If the model's output can't be parsed as valid JSON with a valid route (or if
the Gemini API is temporarily unreachable or misconfigured), the orchestrator
falls back to a simple keyword heuristic **only** to keep the app from
crashing — this fallback path is clearly flagged in the execution trace and
is not the primary routing mechanism.

Examples:

| User request | Route |
|---|---|
| "Summarize the safety policy." | `summarizer` |
| "What is the emergency procedure?" | `qa` |
| "What changed between SOP version 1 and version 2?" | `comparator` |
| "Compare both SOPs and summarize the important changes." | `multi_agent` |
| "What's the weather today?" | `unsupported` |

## 8. RAG (Q&A) workflow

```
User Question → ChromaDB Retriever (top-K, local embedding search)
             → Relevant Document Chunks (+ filename/page metadata)
             → Gemini API (grounded prompt, "don't invent" rule)
             → Answer + Sources
```

Example:

```
Question: What is the emergency shutdown procedure?

Answer: <grounded answer produced only from retrieved chunks>

Sources:
- SOP.pdf — Page 12
```

If no relevant chunks are retrieved, the agent responds:
*"The answer was not found in the indexed documents."*

Only the retrieved chunks (not the whole document) and the question are sent
to Gemini for this step.

---

## 9. Comparator workflow

1. User selects two indexed documents (Document A vs Document B).
2. The full text of each document is reassembled locally from its stored chunks.
3. A line-level diff is computed locally (`difflib`) as a hint for the model.
4. The reassembled document text and diff hints are sent to **Gemini**, which
   performs a **semantic** comparison — not just a character diff — and
   returns Added / Removed / Modified / Unchanged / Important Changes
   sections.
5. The UI renders a structured comparison table plus the full narrative.

## 10. Privacy architecture (updated)

- **No OpenAI, Anthropic/Claude, or Groq API is used anywhere in this codebase.** The only LLM provider is Google Gemini, via the official `langchain-google-genai` integration.
- All LLM inference goes through `models/gemini_client.py`, which calls the Gemini API over the network. **There is no local-LLM fallback and no other cloud provider fallback.**
- **Embeddings remain fully local** — computed by a local `sentence-transformers` model; embedding vectors and the embedding process never touch Gemini or any external API.
- **Vector storage remains fully local** — a persistent ChromaDB instance on disk (`data/chroma/`).
- Uploaded files are copied to `data/uploads/` on the local filesystem only.
- The logger (`utils/logger.py`) intentionally avoids writing full document contents *or the API key* to logs — only metadata (filenames, chunk counts, short redacted snippets) is logged.
- The Gemini API key is read only from the environment (via `.env` + `python-dotenv`), is never hardcoded, never logged, and never displayed in the UI (only a "Configured" / "Missing" status is shown).
- **Data sent to Gemini** includes: the user's query, retrieved/selected document chunks or full document text (for summarization and comparison), and internal routing prompts. If your confidentiality requirements prohibit sending document content to a third-party API, do not use this configuration — consider restoring a local-LLM backend instead.
- This project makes **no claim of regulatory or security certification** (e.g. HIPAA, SOC 2, ISO 27001) and, with Gemini in the loop, **is not an offline or air-gapped system**. Validate against your own organization's compliance requirements before handling real confidential data.

## 11. Settings

Configurable from the **Settings** page (session-scoped):

- Gemini model (default `gemini-2.5-flash`) — you can also use `gemini-2.5-pro` or another model available to your API key
- Temperature (default `0.1`)
- Chunk size / overlap (default `1000` / `150` characters)
- Top-K retrieval (default `4`)

Changing the embedding model requires re-indexing all documents, since
existing vectors were produced by the previous model. Changing the Gemini
model does not require re-indexing (embeddings are unaffected).

## 12. Testing

Run the full test suite:

```bash
pip install pytest
pytest tests/ -q
```

Covered scenarios:

1. Upload a PDF → successfully indexed (`test_ingestion.py`)
2. Ask a question → Q&A retrieves relevant content (`test_agents.py`)
3. Request a summary → Summarizer works (exercised via `test_workflow.py`)
4. Upload two documents → Comparator works (`test_workflow.py`)
5. Natural-language request → Orchestrator selects the correct agent (`test_agents.py`, `test_workflow.py`)
6. Gemini API unreachable / misconfigured → application shows a clear error, not a crash (`test_workflow.py`)
7. Duplicate upload → duplicate is detected (`test_retrieval.py`)
8. Question absent from documents → system clearly says "not found" (`test_agents.py`)
9. Missing `GEMINI_API_KEY` → application surfaces a clear configuration error instead of crashing (`test_workflow.py`)

Tests use a deterministic fake embedding function, a fake/scripted Gemini
client, and an isolated temp ChromaDB directory, so the suite runs fully
offline and **never calls the real Gemini API or your real `data/chroma/`
folder**.

## 13. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Dashboard shows "GEMINI_API_KEY is not configured" | Create `.env` from `.env.example` and set `GEMINI_API_KEY`, or export it in your shell, then restart the app |
| "Test Gemini connection" fails | Check the key is valid and not revoked, check outbound network/firewall access to `generativelanguage.googleapis.com`, check the configured model name is available to your key |
| Upload fails with "no extractable text" | The PDF may be a scanned image with no text layer (OCR not included in this MVP) |
| Comparison seems shallow | Increase chunk size / top-K, or ensure both documents were fully indexed (check Dashboard chunk counts) |
| Responses are slow or rate-limited | Gemini API latency/quota depends on your account tier and the chosen model; try a lighter model like `gemini-2.5-flash` |
| Re-index doesn't do anything visible | Re-indexing requires re-uploading the original file through the Documents page, since raw bytes aren't retained in ChromaDB itself |
| `ImportError` for `langchain_google_genai` | Run `pip install -r requirements.txt` again to ensure the new Gemini dependencies are installed |
